SECTION 05 · SOFTWARE

Software Layer — Multi-Source Alignment, Storage & Reproducibility

Three independent radio links, two time bases, and one conclusion that must still reproduce three months from now. The engineering effort in this layer is usually underestimated in proportion to how decisively it determines experimental success.

5.1　Stack choices

StageChoiceRationale / constraints
BLE ingestbleak (asyncio)cross-platform; needs back-pressure and auto-reconnect
Classic BT ingestpyserialif BITalino is the BT version; slow reconnects affect power-cycle strategy
Raw signalsParquet (columnar)1000 Hz × multi-channel × hours; a relational store doesn't pay off
Telemetry seriesTimescaleDBhypertables + continuous aggregates; EAR integrated per window
ECG processingNeuroKit2R-peak detection and HRV; golden-case regression
DashboardGrafanalive view of energy / temperature / state machine
Run recordsYAML manifest + Gitcommitted alongside the data; never written after the fact
CIpytest + schemaincludes "manifest fw SHA must really exist" check
A discipline that looks pedantic but is the most effective CI verifies that firmware_git_sha in every manifest actually exists in the repo. It forces you to commit firmware first, then run the experiment — not "tweak, run, and forget what changed".
